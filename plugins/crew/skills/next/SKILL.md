description: Start the next task of some colleagues from their todo, or one task the user names: by priority, then the oldest. The Crew panel's Next task button and the ▶ on a backlog row run it; the user may type it too.
argument-hint: "[first names] [-- the task]"

**One task named** (`/crew:next Joseph -- the task`, the ▶ on a backlog row): that line of the colleague's `todo.md`. The user chose it: start it, unless it waits for the user's decision or needs a permission the colleague lacks; then say so in one line and ask. A task led by a number of the project's backlog (`/crew:next Matteo -- T-61 · the board`) is that backlog task, whether a todo line carries it or not: the brief gives its number, and its note when the project plugin's `backlog.mjs show T-61` names one, to read first; the colleague never changes the backlog (Claude marks it done after their report), and ticks their own `T-61` line when they have one.

**Otherwise**, for each colleague named (without names, each one on a coffee break, neither at work nor in the meeting), their next open line, among those of their todo and the tasks of the project's backlog they hold (`backlog.mjs list --to <name>`, when the project has the project plugin): the highest priority (P1, then P2, then P3, then lines without), the oldest within it. Skip the lines waiting for the user's decision, those waiting for an event yet to come (the next playtest, a release), and those the colleague's permissions do not allow; say which were skipped and why when it matters. A colleague with nothing left to start is named in one line.

**A task that waits for others** (`(after: #id)` in its line, the ids found in the todos; `(after: T-62)`, a task of the project's backlog): its chain comes first. Follow each id to its open line, and that line's own `after`, to the start of the chain; a `T-n` to its backlog task (the project plugin's `backlog.mjs show T-62` gives its chain in order, who holds each link and its own `after`), or, without a backlog, to the todo line that carries it. Show the whole chain in one line ("Matteo corrects lootNote → then Elena runs loot2") and ask once. On yes, start the first; when its colleague has ticked their line, or the backlog has the task done, start the next, without asking again, and so on; a link that is Claude's or a person's is not a colleague's task: Claude does its own, and asks the person in the chat, and the chain goes on once it is done. A link that fails stops the chain, and the user is told. A task that waits for an id no longer open is free.

Say in one line per colleague which task starts; when the plan's weekly limit is near (Claude Code: the usage the app shows), ask the user first, since each one is a task. Then each is a task ([task.md](../crew/references/task.md)), all at once and in the background: the line's words are the task, the brief adds what the project's context says about it, where the project keeps the state of its work, and that at the end they tick the line with the day and tidy their todo.
